For judges

The claim

CoinMarketCap says a coin migrated, but only in prose. Successor reads the notice, finds the successor token, checks it against CMC's own rows, and gives the holder one verdict: SWAP, SELL OLD, WRITE OFF, or NOT VERIFIABLE.

The 2-minute path (steps 1–3 take 30 seconds; no login, no keys, nothing to install)

Only ten seconds? Click AGIX on the board, then Receipt: the agent follows the notice's link, code confirms the ratio against CMC's prices, and the receipt shows CMC's own rows.

  1. Open successor.edycu.dev: it runs CPOOL on load (the CPOOL chip re-runs it). The board streams the CMC notice, the Reader's proposal, the code checks and the verdict. On 2026-11-22 03:49 UTC it read SELL OLD (rule R8): CMC's quotes put the old token 15.7% above the 1:1 swap. R8 needs at least 5%; under that margin the same lookup reads SWAP (R9), and its reason gives the margin. CPOOL has shown both, so read the verdict with the capture time on screen.
  2. Click Receipt: the CMC calls behind the verdict, with a copyable curl.
  3. Click the AGIX chip: the trace shows the Reader's recorded run (the trace labels it "recorded extraction") following the notice's link to fetch.ai; code confirms the ratio against CMC prices on the event date, live, verdict SWAP (R9).
  4. Open /?q=GAS&id=1785 (Neo's GAS): its notice quotes a contract (0xd2a4…76cf) that no CMC coin carries, so check C2 fails and the verdict is NOT VERIFIABLE (R5), not a guess.1
  5. Optional, the agent live: on AGIX press Re-read live. The Reader runs now (qwen4-max, live), not from the recording. Three fresh runs on 2026-11-22 each ended SWAP (R9) in 18 to 26 s server time. Fresh reads are limited to 3 per 10 minutes per client; if it errors, the demo video shows a fresh run (real wait about 21 s, labelled speed-up) and docs/proof/assets/agix-fresh-runs-2026-11-22.json holds all three.
  6. Scroll to the census: every notice in CMC's top 2000, with the verdict code gives each. Most end NOT VERIFIABLE, and the page says why.
  7. Prefer a terminal? curl -N 'https://successor.edycu.dev/api/lookup?q=CPOOL&qty=10000'

1 The id is needed because the symbol GAS also matches another coin. The notice may be right: CMC's info?address= knows that hash in neither byte order (docs/proof/spike/09-address-gas-n3.json), so CMC's data cannot confirm it. Raw stream captured 2026-11-22 07:11 UTC: docs/proof/assets/lookup-GAS-2026-11-22T0711Z.ndjson. Captures and the census from before a 2026-11-22 wording change say "successor refuted by CMC's data"; the live board says "fails a check against CMC's data": same rule, same verdict.

If a live lookup errors or runs long (CMC or the model slow), the board says so and shows no verdict. The landing page replays a captured CPOOL lookup, labelled with its capture time (2026-11-22 03:49 UTC); the raw streams are in docs/proof/assets/.

Reproduce (the real path)

git clone https://github.com/edycutjong/successor && cd successor
python3 -m venv .venv && .venv/bin/pip install -e '.[dev]'
export CMC_API_KEY=...  DASHSCOPE_API_KEY=...
SERVE_STATIC=1 .venv/bin/uvicorn api.index:app
# open http://localhost:8000 and click CPOOL

This path calls the real CoinMarketCap Pro API and Qwen. The deterministic offline replay (python scripts/run_evals.py) is a separate eval run over recorded rows, not the product.

Honest limitations

  • Most notices cannot be confirmed from CMC's data alone and end NOT VERIFIABLE; the census page counts them.
  • Verdicts are market-sensitive and can flip between runs; each one carries its capture time.
  • The Reader is slow on a notice it has not seen (seconds, not milliseconds); cached notices answer in about a second.
